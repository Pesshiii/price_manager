# ADR 0009: Разделитель пути категории задаётся в ImportMapping

## Статус
Принято

## Контекст
При импорте продуктов через `ImportJob` категория может передаваться как иерархический путь (например, `"Инструменты/Электроинструмент/Дрели"`). Модель `Category` — MPTT с поддержкой вложенности, но импортёр исторически создаёт только корневые категории (`parent=None`). Нужно добавить разбор пути с настраиваемым разделителем.

Рассматривались три места для настройки разделителя:
1. **Глобальная настройка** (`settings.py` / env var)
2. **Pipeline transform** — трансформ нормализует путь до попадания в маппинг
3. **`ImportMapping`, поле `category`** — `{'column': 'cat', 'path_separator': '/'}`

## Решение
Разделитель задаётся в `ImportMapping` на уровне поля `category` как опциональный ключ `path_separator`.

## Обоснование
- **Против глобальной настройки**: разные поставщики могут использовать разные разделители (`/`, `>`, ` > ` и т.д.). Единственное глобальное значение не покрывает это.
- **Против pipeline transform**: трансформы оперируют сырыми DataFrame и не знают о семантике поля `category`. Добавление категорийной логики в pipeline нарушает разделение ответственности.
- **За `ImportMapping`**: маппинг уже является местом, где описывается семантика каждого поля. `path_separator` — это свойство именно поля `category`, а не всего файла или всего pipeline. Если разделитель не задан, поведение деградирует к прежнему (одна корневая категория) без breaking change.

## Поведение при разборе пути
- Сегменты получаются через `path.split(path_separator)`, каждый проходит `.strip()`, пустые пропускаются.
- Цепочка создаётся сверху вниз: `get_or_create(parent=parent_obj, name=segment)` по паре `(parent, name)`.
- Если после очистки путь пуст — `Product.category` не изменяется (как если бы поле отсутствовало в маппинге).
