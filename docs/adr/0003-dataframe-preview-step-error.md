# ADR-0003: preview-эндпоинт всегда возвращает данные + step_error

**Статус:** Принято — 2026-05-25

## Контекст

При ошибке в transform-шаге N старый preview-эндпоинт возвращал только
`{"error": {"step_index": up_to, "message": "…"}}` без данных (и указывал
`up_to` — запрошенный предел, а не индекс упавшего шага). Пользователь видел
пустой экран вместо последнего валидного состояния DataFrame.

## Решение

`apply_partial` в `dataframe/services.py` оборачивает каждый Transform в
`try/except`. При исключении в шаге K возвращает `(df_до_K, step_error)`.
Preview-эндпоинт всегда отвечает HTTP 200 с полным payload таблицы плюс
`step_error: {step_index: int, message: str} | null`.

Семантика `step_index` — 0-based индекс в массиве `transforms`.

Функция `apply` (используется в Celery-задачах) распаковывает `(df, err)` и
пробрасывает исключение при `err is not None` — внешний контракт для задач
не меняется.

## Рассмотренные альтернативы

| Альтернатива | Почему отклонена |
|---|---|
| HTTP 422 + второй запрос от SPA | Два round-trip вместо одного; SPA усложняется |
| Собирать все ошибки, продолжать pipeline | Ошибка в шаге 2 может скрыть ошибку в шаге 4 (сломанные колонки); пользователь видит неполную картину |
| Оставить текущее поведение | Пустой экран при любой опечатке в конфиге; bad UX |

## Последствия

- Сигнатура `apply_partial` меняется: теперь возвращает `tuple[pd.DataFrame, dict | None]`.
  Обновить: `tests.py:95`, `api/views.py`, функцию `apply` в `services.py`.
- Все текущие Transform начинают с `df.copy()` — при исключении вход не мутируется,
  `df` до шага K корректен без дополнительного копирования.
- Reader-ошибки (неверный формат файла, сессия не найдена) остаются HTTP 404/500 —
  данных нет, возвращать нечего.
