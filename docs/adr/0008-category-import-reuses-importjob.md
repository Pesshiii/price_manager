# Импорт категорий расширяет ImportJob через поле target, а не отдельную модель

Импорт категорий требует тот же SPA-флоу (preview → commit, поллинг статуса, прогресс-бар), что и импорт товаров. Вместо того чтобы создавать отдельную модель `CategoryImportJob` с дублирующимся envelope (`status`, `stage`, `rows_total`, `rows_done`, `result`, `error`), мы добавляем поле `target: 'product' | 'category'` к существующему `ImportJob`. Воркер и SPA выбирают логику по `target`; существующие записи без `target` считаются `'product'`.

**Рассмотренные альтернативы:** отдельная модель `CategoryImportJob` — отклонена, так как полностью дублирует envelope `ImportJob` и требует от SPA знать про два разных типа джобов с идентичным поведением поллинга.
