# ADR-0014: Обнуление остатков отсутствующих товаров гейтится флагом `FeedMapping.is_full_inventory`

**Статус:** Принято (уточняет ADR-0010)

## Контекст

При завершении выгрузки задача ценообразования обнуляла `Stock.quantity` для всех
товаров поставщика, отсутствующих в фиде (документировано в `CONTEXT.md`). Это
неявно предполагало, что **каждая** выгрузка — полный снимок ассортимента
поставщика. Частичная выгрузка (обновление цен, одна категория, акционный лист)
при этом молча обнуляла остатки всего, что в неё не попало. Операция
деструктивна и необратима: исходные `quantity` не сохраняются.

## Решение

Добавить булево поле `FeedMapping.is_full_inventory` (default `False`).
Обнуление остатков отсутствующих товаров выполняется **только** если
`mapping.is_full_inventory` истинно **и** в фиде сконфигурирована колонка с
ролью `stock`. Без колонки остатков фид не несёт данных об остатках, поэтому
обнуление — чистая деструкция и не выполняется. При выключенном флаге фаза
остатков обновляет только товары, присутствующие в фиде, и не трогает остальные.

Деструктивная операция становится **opt-in**. Default `False` выбран потому, что
для необратимой операции консервативный по умолчанию — не разрушать: худший
случай неверно выставленного флага — устаревший остаток (видимый, исправимый),
а не уничтоженный (молча потерянный).

## Следствия

- Меняется поведение для существующих `FeedMapping` на момент миграции:
  поставщики, реально присылающие полный ассортимент, перестают авто-обнулять
  остатки, пока их маппинг не помечен `is_full_inventory=True`. Это намеренно.
- `CONTEXT.md` обновлён: «Stock» и термин `is_full_inventory`.
- Per-session переопределение не вводится — полнота ассортимента считается
  свойством интеграции поставщика, а не отдельного файла (см. `FeedMapping`).
