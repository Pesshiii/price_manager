# ADR-0011: `ProductPrice.supplier` всегда заполнен, расчётные цены отличаются по `rule`

**Статус:** Принято

## Контекст

При проектировании рассматривалось хранить расчётные (прайсовые) цены с `supplier=null`, чтобы отличать их от сырых цен поставщика. Это создаёт неоднозначность: если два поставщика имеют `PricingRule`, производящее один и тот же `PriceType` для одного товара, возникает конфликт на ключе `(product, null, price_type)`.

## Решение

`ProductPrice.supplier` заполнен всегда. Ключ upsert: `(product, supplier, price_type)`. Расчётные цены отличаются по `rule IS NOT NULL`. `PricingRule` всегда привязан к поставщику, поэтому расчётная цена сохраняет поставщика-источника.

## Следствия

- Нет неоднозначности при нескольких поставщиках с одинаковым `dest_price_type`.
- Запрос «все розничные цены товара» возвращает по одной строке на поставщика — агрегация на стороне вызывающего кода.
- Поле `rule` становится основным признаком происхождения цены, а не `supplier`.
