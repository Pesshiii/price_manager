# ADR 0011 — Поле category в импорте товаров всегда интерпретируется как path-строка

## Статус
Принято

## Контекст
При импорте товаров (`target='product'`) поле `category` в маппинге ранее передавалось напрямую в `Category.get_or_create(parent=None, name=raw_value)` — то есть трактовалось как плоское имя корневой категории. Добавляется возможность настраивать разделитель (`separator`) и управлять созданием отсутствующих узлов (`create_missing`).

Два варианта дефолтного поведения:
- **A. Backward-compatible:** separator отсутствует → плоское имя; separator присутствует → path-резолюция.
- **B. Always path:** всегда трактовать как path-строку; separator по умолчанию `>`.

## Решение
Принят вариант **B**: поле `category` всегда интерпретируется как path-строка. Разделитель по умолчанию — `>`. `create_missing` по умолчанию — `false` (отсутствующий путь → невалидная строка).

## Обоснование
Проект находится в стадии разработки, миграция существующих данных нецелесообразна. Вариант A порождает два режима поведения одного поля, что усложняет модель. Вариант B проще: одна семантика, один путь в коде. Категории с символом `>` в плоском имени в продакшене не существуют.

## Последствия
- Существующие маппинги с `category: {column: ...}` без separator начнут использовать `>` как разделитель.
- Если значение в ячейке не содержит separator — это путь с одним сегментом (поведение идентично прежнему при отсутствии `>` в имени).
- При `create_missing: false` (дефолт) строки с неизвестными категориями становятся невалидными — пользователь видит ошибку в preview до commit.
