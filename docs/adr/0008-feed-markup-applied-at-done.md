# Наценки выгрузки применяются при переходе в `done`, результат хранится в `SupplierFeedEntry.data`

Расчётные цены (`FeedMarkupSet`/`FeedMarkupRule`) записываются в `SupplierFeedEntry.data` один раз — при переходе `SupplierFeed → done` — и только для смэтченных записей (`entry.product` заполнен). После этого `data` иммутабельна: изменение правил наценки не пересчитывает исторические сессии.

## Рассматривались альтернативы

**При матчинге (во время обработки выгрузки)** — расчётная цена была бы видна в MatchQueue и могла бы влиять на решение о привязке товара. Отклонено: матчинг и ценообразование — разные ответственности; смешивать их в одном таске усложняет логику и делает матчинг зависимым от корректности правил наценки.

**Лениво, через сериализатор** — `data` хранит только исходные значения, расчёт выполняется на лету при каждом чтении. Отклонено: противоречит принципу `data` как полного снимка строки выгрузки; нагружает каждый API-запрос пересчётом.

## Следствия

Изменение `FeedMarkupRule` после закрытия сессии не влияет на старые записи. Новые правила вступают в силу только для следующей выгрузки. Это намеренно: расчётная цена — часть исторического снимка, а не живой атрибут товара.
