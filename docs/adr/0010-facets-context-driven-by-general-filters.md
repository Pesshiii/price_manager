# ADR 0010 — Фасетные виджеты определяются только общими фильтрами с раскрытием предков категории

**Статус:** принято

## Контекст

На странице продуктов есть два вида фильтров:
- **Общие фильтры** (`q`, `brand`, `category`, `status`) — задают контекстный набор продуктов.
- **Фасетные виджеты** (`char__*`) — фильтрация по характеристикам, список которых должен зависеть от контекста.

Возникли три нетривиальных вопроса:
1. Учитывать ли уже выбранные `char__` фильтры при вычислении виджетов и bucket-счётчиков?
2. Как определить, какие `CharacteristicType` показывать, если `CharacteristicType` привязывается к категории через M2M, а продукты могут лежать в дочерних категориях?
3. Что делать с продуктами без категории?

## Решение

### 1. Facets вычисляются только на контекстном наборе (общие фильтры)

`GET /api/products/products/facets/` игнорирует все `char__*` параметры при вычислении:
- списка показываемых виджетов,
- bucket-счётчиков внутри каждого виджета.

Это Amazon-style фасетирование: выбор одной характеристики не сужает и не убирает виджеты других. Альтернатива (учитывать активные `char__` при подсчёте) приводит к тому, что при выборе двух характеристик счётчики быстро схлопываются в нули — пользователь теряет ориентир.

### 2. Раскрытие предков категории при поиске CharacteristicType

Для каждой уникальной категории из контекстного набора берутся все её предки вплоть до корня (`get_ancestors(include_self=True)`). `CharacteristicType` показывается как виджет, если он привязан (M2M) хотя бы к одной категории из этого расширенного множества.

Альтернатива (только точная категория продукта) означает, что `CharacteristicType`, назначенный на родительскую категорию, никогда не появится в фильтрах дочерних продуктов. Это вынуждает привязывать каждый тип к каждому листовому узлу вручную — практически неприемлемо для глубоких деревьев.

### 3. Виджет показывается только при наличии значений

Даже если `CharacteristicType` формально привязан к категории, виджет не рендерится, если ни у одного продукта контекстного набора нет значения этой характеристики. Пустые виджеты бесполезны и захламляют UI.

### 4. Продукты без категории не участвуют в определении виджетов

`product.category = NULL` → продукт исключается из расчёта множества релевантных категорий и char types. Его характеристики могут появиться в bucket-счётчиках только если соответствующий `CharacteristicType` привязан к категории другого продукта из контекстного набора.

## Последствия

- `facets` action в `ProductViewSet` переписывается: строит отдельный QS с только общими фильтрами, затем делает два дополнительных запроса (distinct category ids → ancestor expansion → CharacteristicType M2M).
- Количество виджетов ограничено `facets_max_keys` (дефолт 50); при превышении берутся топ по суммарному числу значений.
- Прежнее поведение (учитывать `char__` при подсчёте facets) удаляется без версионирования — оно противоречит принятой модели.
