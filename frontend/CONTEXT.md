## Glossary

### Поставщик (Supplier)
Организация, поставляющая товары. Имеет только имя (`name`). Может быть привязана к фидам и маппингам фидов — удаление заблокировано (`409`), пока существуют связанные объекты.

### Фид (SupplierFeed)
Одна сессия загрузки прайс-листа от поставщика. Жизненный цикл: `draft` (загрузка файлов) → `processing` (Celery-задача матчинга) → `matched` (все строки сопоставлены автоматически) / `partial` (часть строк в MatchQueue) → `done` (очередь разобрана вручную), либо `error` при падении задачи. Содержит список `session_ids` загруженных файлов и записи (`SupplierFeedEntry`).

### MatchQueue
Виртуальная очередь — фильтр `SupplierFeedEntry` с `product=null, skipped=false`. Не отдельная модель. Пользователь разбирает записи вручную: подтверждает кандидата, ищет товар вручную, создаёт новый товар, пропускает запись или игнорирует SKU навсегда. После разбора последней записи фид автоматически переходит в `done`.

Доступные действия над записью:
- **Подтвердить** — привязать кандидата (`resolve/ {product_id}`), создаёт `SupplierLink`.
- **Найти вручную** — поиск по каталогу, затем подтвердить.
- **Создать товар** — создать новый `Product(status=draft)` прямо из записи (`create-product/ {sku, name}`), одновременно создаёт `SupplierLink` и закрывает запись.
- **Пропустить** — пометить запись как пропущенную в этой сессии (`resolve/ {skipped: true}`), без долгосрочного эффекта.
- **Игнорировать** — создать постоянный игнор-линк (`ignore/`), SKU поставщика будет автоматически пропускаться во всех будущих фидах без попадания в очередь.
- **Создать все оставшееся** — массовое действие (`bulk-create-products/ {name_column}`): создаёт `Product(status=draft)` + `SupplierLink` для каждой нерешённой записи за один запрос. Колонка для имени товара выбирается из `FeedMapping.identity_columns + variable_columns`, preselect из `FeedMapping.product_name_column`. Ошибочные записи (конфликт SKU, пустое поле) пропускаются и остаются в очереди. Если очередь опустела — фид переходит в `done`.

### Маппинг (FeedMapping)
Шаблон конфигурации, описывающий формат файлов конкретного поставщика. Ссылается на Dataframe-пайплайн, который применяется к каждому загружаемому файлу перед матчингом.

### Запись фида (SupplierFeedEntry)
Одна строка выгрузки внутри `SupplierFeed`. Поле `data` содержит объединение identity-колонок и variable-колонок из `FeedMapping` (оба набора попадают в запись). Поле `match_candidates` — топ-N кандидатов с полями `{product_id, score, name, sku, category, brand}`, денормализованными в момент матчинга.

### Ссылка (SupplierLink)
Постоянное соответствие `supplier_sku → Product`, накапливаемое из разрешённых записей фидов.

### Товар (Product)
Единица каталога с JSONB-характеристиками. Идентифицируется по `sku`.

### Характеристика (Characteristic)
Пара ключ-значение в JSONB-поле `Product.characteristics`. Тип определяется `CharacteristicType`.

### Тип характеристики (CharacteristicType)
Схема для значения характеристики: имя (ключ в JSONB), тип значения (`value_type`), единица измерения, список допустимых значений (`options`), привязка к категориям.

## Каталог товаров — таблица и фильтры

### Выбор колонок (ColumnPicker)
Пользовательская настройка видимых колонок таблицы продуктов. Хранится в `localStorage`. Два типа колонок:

- **Обязательные** (`SKU`, `Название`) — нельзя скрыть.
- **Опциональные базовые** (`Категория`, `Бренд`, `Статус`, `Дата обновления`) — включены по умолчанию.
- **Ценовые** (по одной на `PriceType`) — выключены по умолчанию. Список берётся из `GET /api/pricing/price-types/`.

Пикер открывается кнопкой у таблицы (Popover с чекбоксами).

### Ценовая колонка
Колонка таблицы, соответствующая одному `PriceType`. Показывает **минимальную** цену товара среди всех поставщиков с этим типом. Запрашивается через параметр `?price_types=<slug>,<slug>` на `GET /api/products/products/`; бэкенд аннотирует каждый продукт полем `prices: { [slug]: number | null }`.

### Фильтр по цене
Секция в сайдбаре фильтров: `Select` для выбора `PriceType` + два числовых поля «от / до». Параметры запроса: `?price_type=<slug>&price_min=<N>&price_max=<N>`. Всегда виден — независим от того, какие ценовые колонки активны в таблице.

## Трансформация выгрузки

### Снимок (ProductSnapshot)
Нормализованный набор полей товара от конкретного поставщика, результат применения правил трансформации к матченым строкам выгрузки. Ключ: `(product, supplier)` — один снимок на пару, каждая новая выгрузка перезаписывает. `data` — плоский JSON-словарь `{slug: value}`. Создаётся автоматически, недоступен для записи через API.

### Поле снимка (SnapshotField)
Запись системного справочника допустимых ключей снимка. Поля: `slug` (уникальный идентификатор, ключ в `data`), `name` (русское название), `value_type` (`number | string | boolean`), `description`. Общий для всех поставщиков. Удаление заблокировано (`409`), если есть ссылающиеся правила.

### Правило трансформации (TransformRule)
Инструкция `{priority, target_field, condition, formula}`, вычисляющая одно поле снимка. Привязана к `FeedMapping` (FK). Правила сортируются по `priority` (меньше = выше приоритет); первое сработавшее для данного `target_field` побеждает. `condition: null` означает «всегда истина».

### Условие (Condition)
Структурированный JSON. Логические узлы: `{"op": "AND|OR", "conditions": [...]}`, `{"op": "NOT", "condition": {...}}`. Листовой узел: `{"op": "==|!=|<|<=|>|>=", "source": "feed|char|brand|category", "key": "...", "value": <литерал>}`. `source: "brand"` и `source: "category"` — без поля `key`.

### Набор наценок (FeedMarkupSet)
Конфигурация ценообразования, привязанная к `FeedMapping` (FK). Определяет пару: колонка-источник цены (`price_column` — из вывода пайплайна) и ключ результата (`output_column` — пишется в `SupplierFeedEntry.data`). Один маппинг может иметь несколько наборов (напр. закупочная → розничная, закупочная → оптовая). Наценки применяются однократно при переходе фида в `done`; обновляются только матченые записи.

### Правило наценки (FeedMarkupRule)
Покрывает диапазон входных цен (`price_from`–`price_to`, включительно, `null` = открытый конец). Формула: `output = price × (1 + markup / 100) + increase`. Приоритет определяется полем `order` (меньше = выше); первое сработавшее правило побеждает. Если ни одно правило не покрывает цену или колонка отсутствует/нечисловая — `output_column` не записывается.

### Формула (Formula)
Структурированный JSON, пять вкладываемых типов. `copy` — копирование поля: `{"type": "copy", "source": "feed|char", "key": "..."}`. `literal` — константа: `{"type": "literal", "value": ...}`. `arithmetic` — арифметика (`+`, `-`, `*`, `/`) двух подформул. `map` — маппинг значений словарём с `default`. `if` — условная ветка: `{"type": "if", "condition": <Condition>, "then": <Formula>, "else": <Formula>}`. Вычисляется сервером без `eval`.
