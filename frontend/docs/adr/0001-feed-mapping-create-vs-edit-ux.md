# ADR-0001: FeedMapping — визард при создании, форма при редактировании

**Статус:** Принято  
**Дата:** 2026-05-31

## Контекст

Страница поставщика (`/suppliers/:id`) должна позволять создавать и редактировать `FeedMapping`. При создании обязателен шаг выбора/создания Dataframe-пайплайна — без пайплайна маппинг невалиден. При редактировании пользователь чаще всего правит одно поле (порог, колонку).

## Решение

**Создание** — двухшаговый визард:
1. Выбор существующего пайплайна из списка **или** создание нового через `DataframeBuilder` в Drawer (без перехода на `/dataframe/new`).
2. Заполнение полей маппинга: `name`, `supplier_sku_column`, `identity_columns`, `variable_columns`, `auto_match_threshold`.

**Редактирование** — единая форма на `/suppliers/:id/mappings/:mappingId/edit`: все поля сразу, пайплайн меняется через тот же Drawer по кнопке «Изменить».

**Выбор колонок** (шаг 2 и форма редактирования): `MultiSelect` с `creatable`. Если на шаге 1 был загружен тестовый файл и получен успешный preview — колонки из него подставляются как варианты. Если пайплайн выбран без файла — только ручной ввод.

## Альтернативы

- Один визард и для создания, и для редактирования — избыточное трение при точечных правках.
- Полная навигация на `/dataframe/new` при создании пайплайна — разрывает поток, теряется контекст поставщика.

## Последствия

Асимметрия create/edit — норма для этого паттерна (аналог `products/new` vs `products/:id/edit`). Drawer с `DataframeBuilder` переиспользуется в обоих случаях.
